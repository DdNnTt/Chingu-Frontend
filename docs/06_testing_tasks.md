## 2. 컴포넌트 단위 테스트 추가 (Unit / Component)

> 기준: “구현이 아니라 행동을 테스트한다”

### 2-1) 테스트 대상 선정

- [ ] 이번 리팩토링으로 분리/변경된 컴포넌트 식별
- [ ] 조건 분기 / 상태 분기 로직이 있는 컴포넌트 식별
- [ ] 재사용 가능성이 있는 UI 컴포넌트 식별

### 2-2) 테스트 작성

- [ ] React Testing Library로 사용자 행동 기반 테스트 작성
- [ ] 테스트 시나리오:
  - [ ] 렌더링이 정상적으로 되는가
  - [ ] 사용자 액션(click, input)에 따른 결과가 맞는가
- [ ] 금지 패턴 확인
  - [ ] state, className, hook 내부 구조 직접 테스트 ❌
- [ ] 권장 패턴 적용
  - [ ] 화면에 보이는 텍스트/요소 존재 여부로 검증 ⭕

## 3. E2E 테스트 범위 점검 (선별 적용)

> 원칙: “모든 화면 ❌, 중요한 흐름 ⭕”

### 3-1) 핵심 사용자 플로우 식별

- [ ] 로그인 / 로그아웃
- [ ] 회원가입
- [ ] 데이터 생성 / 수정 / 삭제
- [ ] 권한이 걸린 페이지 접근

### 3-2) E2E 테스트 적용 여부 판단

- [ ] 이번 PR이 핵심 플로우에 영향을 주는가?
  - [ ] YES → E2E 테스트 추가 또는 기존 테스트 보강
  - [ ] NO → 이번 PR에서는 E2E 제외 가능(사유 메모)

## 4. 엣지 케이스 테스트 추가

> 리팩토링 시 가장 많이 터지는 영역

- [ ] 데이터가 null / undefined인 경우
- [ ] 빈 배열 전달 시
- [ ] API 지연 상태(isLoading)
- [ ] API 에러 응답
- [ ] 권한 없는 사용자 접근

```ts
expect(() => render(<Component data={[]} />)).not.toThrow()
```
